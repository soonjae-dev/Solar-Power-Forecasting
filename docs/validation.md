# 검증 설계

## 원칙

1. **시간 순서 준수**: 무작위 분할 미사용. 각 구간의 첫 대상일 전날 17:00까지의 정답과 예보만으로 학습
2. **평가 시점에 없는 정보 배제**: 실측 기상, 발전 실적 lag, 대상일 SMP, 대상일 이후 발행 예보가 해당
3. **외부 예보의 공개 시각 감사**: 날짜마다 원격지 파일의 Last-Modified가 예측 시점(전날 08:00 UTC)보다 이른지 확인한 실행분만 사용
4. **미관측 발전소의 0 채움 금지**: 실적이 있는 발전소-시각만으로 집합 점수를 계산
5. **단일 변경 및 동일 시드 비교**: 한 번에 한 가지만 변경하고 같은 시드끼리 비교

## 검증 구간

| 구간 | 기간 | 용도 |
|---|---|---|
| 여름 | 2024-06 \~ 08 | 계절별 판정 |
| 가을 | 2024-09 \~ 11 | 계절별 판정 |
| 겨울 | 2024-12 \~ 2025-02 | 계절별 판정 |
| 봄 | 2025-03 \~ 04 | 계절별 판정 |
| 고정 11개월 | 2024-06 \~ 2025-04 | 2024-05 마감 모델 하나로 예측(1년 평가 모사) |
| OOF 1 \~ 5 | 2022-01 \~ 2024-05 | 사후 보정 학습용 시간순 표본 밖 예측 |
| holdout | 2025-05 | v3 선택 후 첫 채점(+16.6점), 이후 GFS 후보 확인에 2회 추가 사용(p27, 선택에는 미사용) |

계절 구간마다 별도의 학습 마감을 두어, 마감에서 가까운 예측과 먼 예측을 함께 평가하였다. 사후 보정은 2022-01 \~ 2025-04를 연도 블록 4개로 나누고, 한 블록을 제외하고 학습한 뒤 그 블록에서 채점하는 교차검증을 사용하였다.

## 채택 기준 (모든 실험에 결과 확인 전 고정)

- 4계절 페널티 변화 합 ≤ −1%
- 4계절 중 3계절 이상 개선
- 가장 나쁜 계절 ≤ +3%
- 고정 11개월 ≤ 0%
- 7일 블록 부트스트랩 90% 구간을 함께 기록. 사후 보정에는 '구간 상한 < 0'을 추가로 요구한 경우도 있음
- 1시드로 통과하면 3시드로 재확인한 뒤 제출 후보로 선정

## 제출 운영

- 사전 기준을 통과한 후보만 제출 파일로 생성
- 후보마다 정의, 기대 효과, 적용 범위를 제출 전에 문서로 고정. 1회만 제출하고, 점수 확인 후 배율·혼합·배정을 수정하지 않음(대회 운영 공지)
- 모든 제출은 공식 형식 검사를 통과해야 하며, 제출 기록에 코드·구성·예측 해시를 등록

## 채점기

- `src/scoring.py`에 대회 산식을 구현. 자체 검사(`--selftest`)는 완전 예측, k = 1·3, SMP = 0, 집합 간 반대 오차, 집합 내 상쇄, 하한, 용량 미달을 포함
- 제공 노트북의 기준선 페널티(29,690,634원)를 로컬에서 동일하게 재현
- 서버의 S 차이와 로컬 기대값의 자릿수·부호 일치 여부를 매 제출마다 대조

## 한계 (사후 확인 사항)

- **1년에 집중된 표본 밖 근거**: 253개소가 모두 관측된 기간이 짧아, 계절 구간과 고정 11개월이 모두 2024-06 \~ 2025-04 안에 위치함
  - 그해 모델은 실적보다 1.3% 과대예측함
  - 그 결과 예측을 낮추는 변경이 로컬에서 체계적으로 유리하게 나타남
  - 이 편향으로 로컬과 서버 결과가 세 차례 엇갈림([lessons.md](lessons.md))
- **보완 기준**: 사후 보정은 연도 블록 교차검증에 더해, 기준 예측에 상수 배율(0.96 \~ 1.10)을 먼저 곱했을 때도 효과가 유지되는지 확인
